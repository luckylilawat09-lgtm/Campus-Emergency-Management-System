# Project Statement – SentriCampus

## Statement

SentriCampus is a Java project built around a simple campus problem: emergencies can be very different in nature, but they still need to be recorded and handled in an organized way.

The project models incidents such as medical emergencies, fires, security issues, accidents, and utility failures. Each incident stores basic information such as its location, severity, reporter, type, and current status. The model also represents campus resources and checks whether a resource is appropriate for a particular emergency.

The main purpose of this stage is to build a strong object-oriented foundation. Abstract classes are used for common behaviour, inheritance is used to create specialized emergency and resource types, and polymorphism allows the program to work with different objects through common parent types. Encapsulation is used to keep important data controlled, while constructor overloading and method overriding are also demonstrated.

The current implementation is intentionally limited to the core model. It demonstrates how emergencies and resources can interact, including priority calculation, compatibility checking, and basic resource assignment. Features such as databases, authentication, graphical interfaces, and more advanced dispatch logic can be introduced in later stages.

Overall, SentriCampus is intended to show how Java OOP concepts can be applied to a practical campus-management scenario instead of being demonstrated only through isolated examples.

## Objective

The objective of this stage is to create a clear and extendable Java model for campus emergency handling while demonstrating the major object-oriented programming concepts required by the project.

## Expected Outcome

The expected result is a working Java model in which different emergency types can be created, described, prioritized, matched with suitable resources, and assigned while keeping the code organized enough for future development.
